# acktvt launcher — acktvt.prowessz.com

A single static page that covers the Render cold start. Someone opening a
workspace after a quiet spell used to stare at a blank tab for half a minute;
now they get a branded page that tells them what is happening, wakes the
service in the background, shows something worth reading while they wait, and
forwards them the moment the server answers.

It replaces the old one-link holding page and serves **both** suites from this
one repo.

## URLs

| URL | What happens |
|---|---|
| `https://acktvt.prowessz.com/` | The chooser: two cards, Data Protection Suite and Business Management Suite. Both services are pinged quietly in the background, so whichever the person picks has a head start. |
| `…/?app=dps` | Wakes the Data Protection Suite and forwards to its sign-in page. |
| `…/?app=bms` | Wakes the Business Management Suite and forwards to it. |
| `…/?app=dps&next=/signup` | Same, but lands on a specific path — used by the "Sign up for a free trial" button on acktvt.com. |

`next` is accepted only when it resolves to the same origin as the app's own
address, so the page cannot be turned into an open redirect by someone editing
the query string.

## The only thing you normally edit

Near the top of the `<script>` block in `index.html`:

```js
var APPS = {
  dps: { name: …, lead: …, url: 'https://dps.acktvt.com/login',
         probe: 'https://dps.acktvt.com/', tips: [ … ] },
  bms: { name: …, lead: …, url: 'https://erp.acktvt.com',
         probe: 'https://erp.acktvt.com/',  tips: [ … ] }
};
```

* `url` — where the person ends up.
* `probe` — what gets requested to wake the service. Same origin as `url`; the
  root is usually right.
* `tips` — the four cards that rotate while they wait, as
  `[icon, heading, body, link, link text]`. Leave the last two empty for a card
  with no link.

**When the addresses change** (moving off `onrender.com`, adding a subdomain),
change them here and nowhere else. The buttons on acktvt.com point at this
page, not at the products, so they keep working.

## How the wake works

The page requests `probe` with `mode: 'no-cors'`. The response is opaque — we
never read it, and no CORS header is needed on either product. What matters is
that the request *completed*, which is precisely what "the service is awake"
means. A sleeping Render service refuses or hangs, the request fails, and the
page tries again every 1.5 seconds.

The progress bar eases toward 92% over roughly 45 seconds and only reaches 100%
when the server actually answers — it reports elapsed time honestly rather than
pretending to know the remaining time. After 70 seconds it says it is taking
longer than usual; after 150 it stops knocking and offers the direct link and
the support address.

## Files

| File | Purpose |
|---|---|
| `index.html` | The whole page — markup, styles and script in one file, no web fonts and no external requests, so it paints instantly. |
| `assets/favicon-64.png`, `assets/apple-touch-icon.png` | acktvt icon. |
| `prowessz-logo.png` | **Keep the existing file at the repo root.** The header shows it beside the acktvt mark; if it is missing the image hides itself and the page still reads correctly. |

## Deploying

GitHub Pages serves the repo root. Commit and push; the page is live in a
minute. There is nothing to build.

`noindex,nofollow` is set — this is a doorway for clients, not a page that
should turn up in search results ahead of acktvt.com.

## Where it is linked from

* **acktvt.com** — the *Client login* button in the header, the *Client portal*
  link in the footer, and the two cards plus the trial button on
  `acktvt.com/login/`. Those are generated by `build_pages.py` in the
  `acktvt-site` repo, from the `LAUNCH_*` constants near the top.
* Anywhere you would previously have pasted a raw Render URL — e-mail
  signatures, the Android app's "open in browser", printed cards.
